# Phi-1：Textbooks Are All You Need

**论文**：*Textbooks Are All You Need*（Gunasekar et al., 2023）
**arxiv**：2306.11644
**机构**：Microsoft Research
**发表**：2023 年 10 月（arXiv）

## 核心问题

**训练代码生成模型需要多少数据，以及什么样的数据？**

既有的代码模型（Codex、StarCoder、WizardCoder）要么参数量巨大（15B+），要么训练数据海量（800B+ tokens），而且大多数代码数据来自 GitHub，充斥着样板代码、非自包含的代码片段和低密度的教学内容。

phi-1 的核心主张：**用"教科书质量"的数据训练，1.3B 参数 + 7B tokens 就能在代码生成上超越大多数更大的模型**，HumanEval pass@1 达到 50.6%，超过参数量是它 10 倍以上的 StarCoder（33.6%）和 CodeGen-Mono-16.1B（29.3%）。

## 三个数据集

phi-1 只用了三个数据集，总量不到 7B tokens：

### 1. filtered code-language（~6B tokens）

从 The Stack 和 StackOverflow（合计 35M+ 文件，35B+ tokens）筛选出高教育价值的子集。

**两个数据池的区别**：
- **35B tokens**：The Stack + StackOverflow 的全量 Python 代码，原始数据，质量参差不齐
- **10 万份标注样本**：从 35B tokens 中随机抽取的一小部分（约 0.03%），用来给分类器提供训练信号

**筛选流程**：
1. 从 35B tokens 里随机抽取约 10 万份代码文件
2. 用 GPT-4 对这 10 万份标注"对初学者的教育价值"（0-10 分）——只需要标注这一小批，不是全部 35B
3. 用这 10 万条标注，训练一个**[随机森林](../20-concepts/random-forest.md)分类器**
4. 用分类器对全部 35B tokens 打分，只保留高分样本（约 6B tokens）

**codegen 模型是什么**：CodeGen（Nijkamp et al., 2022，Salesforce）是当时一个开源的代码生成模型，有 350M/2B/6B/16B 等规模。phi-1 用的是 codegen-350M-mono（仅 Python 版本）。

**随机森林怎么做**：
```python
# 1. 对每个代码文件，用 codegen-350M-mono 提取 embedding
#    方法：把文件 token 化后跑一次前向传播，取最后一层的平均 hidden state
#    每个文件变成一个固定长度的向量（如 1024 维）

embeddings = [codegen_encoder(file) for file in sampled_100k_files]  # shape: (100k, 1024)
labels = gpt4_quality_scores  # shape: (100k,)，0-10 的整数

# 2. 用这 10 万个 (embedding, score) 对训练随机森林
#    embedding 的 1024 维直接作为 1024 个特征输入——随机森林看到的是一个 1024 列的表格
from sklearn.ensemble import RandomForestClassifier
clf = RandomForestClassifier(n_estimators=100)
clf.fit(embeddings, labels)

# 3. 对全量 35B tokens 的每个文件打分，保留高分
for file in all_35B_tokens:
    emb = codegen_encoder(file)
    score = clf.predict([emb])[0]
    if score >= threshold:
        keep(file)
```

[随机森林](../20-concepts/random-forest.md)（多棵决策树投票）在固定长度向量上训练快、效果稳，CPU 即可运行。提取 codegen embedding 的方法：把代码文件输入 codegen-350M-mono，跑一次前向传播（不生成任何 token），取最后一层所有位置 hidden state 的均值，得到约 1024 维向量；上下文窗口 2048 tokens，超长文件截断处理。

**三路分工的设计逻辑**：**GPT-4** 有 instruction following 能力，能理解「评估初学者教育价值」这个元任务并输出分数，但全量 3500 万次调用约需 $130 万；**codegen** 没有经过 instruction tuning，无法直接打分（输入「给这段代码打分」它会当代码续写），但 hidden state 携带了真实的代码语义，前向传播在自己的 GPU 上运行极便宜；**随机森林** 用 GPT-4 的 10 万个标注学习「语义向量 → 质量分数」的映射，推理时需对全量 35B tokens 跑一遍 codegen embedding（8×A100 约 6 小时）。这个「强模型注解小样本 → 训练轻量代理 → 规模化」的模式后来被广泛复用（DCLM 用 fastText 直接吃文本，连 embedding 那步也省掉了）。

| 方案 | GPT-4 调用 | GPU 计算 | 估算费用 |
|------|-----------|---------|---------|
| GPT-4 全量打分 | 3500 万次（~$1,200/百万 tokens） | — | ~$130 万 |
| phi-1 方案 | 10 万次 | codegen 前向传播，8×A100 ~6 小时 | ~$2200 |

**分类器的打分结果去哪了**：分类器的输出分数直接决定哪些文件进入训练集。高分文件（约 6B tokens）构成 filtered code-language 数据集，用于预训练阶段。分类器本身训练完就丢弃，它只是一个"过滤工具"，不是模型的一部分。整个流程：35B → 分类器打分 → 保留 6B → 加入 CodeTextbook → 训练 phi-1-base。

**高/低教育价值的区别**（论文 Figure 2.1 展示）：
- **高价值**：有清晰 docstring、独立可运行、展示算法逻辑（如 normalize、euclidean_dist）
- **低价值**：大量样板代码（GUI 配置、类型注解初始化），逻辑不透明，依赖外部上下文

### 2. synthetic textbook（<1B tokens）

用 GPT-3.5 生成的 Python 教科书，自然语言和代码交织，覆盖推理和基础算法技能。

**多样性保证**：每次生成时随机注入一组词汇约束（"这本教科书必须涵盖 X、Y、Z 话题"），迫使生成内容覆盖不同概念组合，避免重复。

示例（矩阵奇异性判断）：先用自然语言解释概念，再给出 Python 实现，再给练习题——正是教科书的结构。

### 3. synthetic exercises（~180M tokens，仅用于 finetuning）

GPT-3.5 生成的 Python 函数补全练习：每道题是一个带 docstring 的函数签名，要求补全实现。

多样性策略：随机约束函数名称，避免模型重复生成同类题目。

**这三个数据集共同构成两个训练阶段**：
- **预训练（phi-1-base）**：filtered code-language + synthetic textbook（合称 CodeTextbook，~7B tokens，训练 8× A100，约 4 天）
- **微调（phi-1）**：在 phi-1-base 基础上，用 synthetic exercises 微调（同样的 8× A100，额外 7 小时）

**数据量是怎么定的**：论文没有给出严格推导，这些数字是实验选定的：
- **预训练 6B（filtered）+ <1B（textbook）≈ 7B tokens**：在计算预算（8× A100，约 4 天）内能多轮训练（约 8 个 epoch）的量。论文发现在这个数据规模下，多遍训练比单遍训练效果好——数据质量高时重复学习有益而非过拟合。
- **微调 ~180M tokens（exercises）**：故意设计得小，一方面是为了验证"小而精的微调数据就能激发涌现"，另一方面是要保证 CodeExercises 和 HumanEval 的重合可控（Section 5 做了去污染分析）。
- 这些比例的选择逻辑是：预训练数据要覆盖宽而广的代码知识（所以 6B filtered + 教科书），微调数据要对齐特定任务格式（函数补全），不需要大。

## 模型结构

标准 decoder-only Transformer，无任何架构创新：

| | phi-1（主模型） | phi-1-small（小版本）|
|--|--------------|-------------------|
| 参数量 | **1.3B** | 350M |
| 层数 | 24 | 20 |
| Hidden dim | 2048 | 1024 |
| MLP inner dim | 8192 | 4096 |
| 注意力头数 | 32 | 16 |

使用 FlashAttention、rotary position embedding，tokenizer 与 codegen-350M-mono 相同。训练用 fp16 + AdamW，sequence length 2048。

论文明确强调：**模型架构和训练方法都是常规的，创新完全来自数据**。

## 实验结果

### HumanEval 对比（pass@1）

| 模型 | 参数量 | 训练 tokens | HumanEval |
|------|--------|------------|-----------|
| Codex-12B | 12B | 100B | 28.8% |
| CodeGen-16.1B | 16.1B | 577B | 29.3% |
| StarCoder | 15.5B | 1T | 33.6% |
| WizardCoder | 16B | 1T | **57.3%** |
| **phi-1** | **1.3B** | **7B** | **50.6%** |
| phi-1-small | 350M | 7B | 45% |
| GPT-4 | N.A. | N.A. | 67% |

phi-1 用 **1/10 的参数、1/100 的训练数据**，达到比 StarCoder 高 17pp 的性能。WizardCoder 略高，但参数量是 phi-1 的 12 倍。

### 涌现能力（Section 3）

微调在 CodeExercises 上带来的提升，远超出 CodeExercises 的题目范围：

- **外部库使用**：CodeExercises 几乎不含 PyGame 和 Tkinter 代码，但微调后 phi-1 能正确实现 PyGame 游戏逻辑和 Tkinter GUI——说明微调触发了预训练中已有但未被激活的能力
- **phi-1-base vs phi-1**：两者的差异不只是"会不会补全函数"，phi-1 展现出对复杂逻辑的真正理解（能正确处理 Alice/Bob/Charles 游戏逻辑），phi-1-base 只是语法上正确但语义错误

论文把这种现象称为**"涌现"（emergent capabilities）**：不在微调数据集里的能力，在微调后突然出现。

### 数据消融

| 训练数据 | 350M 模型 HumanEval |
|---------|-------------------|
| The Stack +（原始，未过滤） | 11% |
| CodeTextbook（过滤 + 合成教科书） | 20% |
| CodeTextbook → CodeExercises | **41%** |

每一步数据质量提升带来的收益远超计算量的增加。

## 局限性

1. **只针对代码，特别是 Python**：论文聚焦函数补全任务（HumanEval/MBPP），多语言代码、通用语言理解未验证
2. **合成数据细节未公开**：生成教科书和练习题的 prompt 没有完整公开（"for proprietary reasons"），复现存在障碍
3. **GPT-4 注解的代价**：初始的质量分类器依赖 GPT-4 对 10 万样本的标注，这部分成本不可忽视
4. **测试集污染问题**（Section 5）：论文专门分析了 CodeExercises 和 HumanEval 的重叠，采取了去污染措施，但合成数据的污染风险仍是已知局限
5. **性能天花板**：1.3B 参数在 GPT-4（67%）面前仍有明显差距，对于需要真正复杂推理的题目力不从心

## 现状与影响

**定性：奠基性工作，直接催生了 Phi 系列的持续演进。**

phi-1 是"数据质量决定模型能力"这个命题的第一个令人信服的大规模验证。它发表后直接推动了 Microsoft 的 Phi-2（2023 年底，2.7B 参数，扩展到通用推理）和 Phi-3 系列（2024，3.8B-14B，在多项任务上接近 Llama 3 70B）。

在更广的影响上：
- 证明了"合成数据可以替代甚至优于真实数据"，这个结论此后被 LIMO、Phi-3、Apple 等大量工作验证和扩展
- "用强模型注解 → 训练轻量分类器 → 规模化打分"的流程，成为工业界数据质量管道的标准范式之一
- 直接挑战了"更多数据总是更好"的直觉，和 LIMO（817 条 SFT 数据激发推理）是同一逻辑在不同场景（代码 vs 数学）的独立验证

**当前（2026）视角**：phi-1 本身已经过时（Phi-3-mini 3.8B 远超它），但它提出的问题——"什么是高质量数据，如何规模化获取"——仍是 LLM 数据工程的核心问题。

## 和 wiki 内其他概念的关联

- **[DoReMi](./doremi-2305.10429.md)**：同样关注数据质量和配比，方向互补——phi-1 解决"什么是好数据"，DoReMi 解决"各来源比例怎么定"
- **[LIMO](./limo-2502.03387.md)**：同一逻辑在数学推理的验证——少量高质量 SFT 数据激发能力，phi-1 是代码领域的先行版本
- **[Loss Functions](../20-concepts/loss-functions.md)**：phi-1 的训练目标是标准 NLL（next-token prediction），但数据质量的差异导致了截然不同的结果——同一个 loss，不同数据，天壤之别
