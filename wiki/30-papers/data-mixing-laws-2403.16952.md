# Data Mixing Laws: Optimizing Data Mixtures by Predicting Language Modeling Performance

**arxiv**: 2403.16952 | **年份**: 2024 | **机构**: Fudan University, Shanghai AI Laboratory | **接收**: ICLR 2025

**作者**: Jiasheng Ye, Peiju Liu, Tianxiang Sun, Jun Zhan, Yunhua Zhou, Xipeng Qiu

**代码**: https://github.com/yegcjs/mixinglaws

---

## 核心问题

预训练数据通常由多个领域混合而成（网页、代码、学术论文等），各领域的比例（mixture proportions）对模型效果有显著影响。现有方法依赖启发式规则或定性判断来调整比例，**无法在训练前预测不同配比对应的模型性能**。

核心问题：能否在不实际训练的情况下，定量预测任意数据配比下的模型验证损失？

---

## 方法 / 核心机制

### 1. Data Mixing Laws（数据混合定律）

论文发现：在固定模型大小和训练步数的情况下，**第 i 个验证域的损失与训练域比例之间满足指数函数关系**：

$$L_i(r_{1\ldots M}) = c_i + k_i \exp\left(\sum_{j=1}^{M} t_{ij} r_j\right)$$

其中：
- $r_j$ 是第 j 个训练域的比例
- $c_i$、$k_i$、$t_{ij}$ 是可学习参数
- $t_{ij}$ 的正负反映域间关系：$t_{ij} < 0$ 表示训练域 j 有助于降低验证域 i 的损失（facilitation）；$t_{ij} > 0$ 表示 conflict

**直觉理解**：这个公式说的是，"你给某个领域喂多少数据，模型在那个领域的损失就会按指数规律下降"。$c_i$ 是不可再降低的底线损失（数据熵），$k_i \exp(\cdots)$ 是"还能再降多少"。$t_{ij}$ 反映的是领域之间的互动——代码数据不仅帮助代码域，也可能（以负 $t_{ij}$）帮助数学域，因为两者共享逻辑结构。论文做的事就是：**用几十组小实验拟合出这些参数，然后用公式预测出你没跑过的任意配比会得到什么损失，从而找最优配比**。

整体验证损失 = 各域损失的加权求和（显式域聚合），或通过**隐式域聚合**端到端拟合（将验证集的域比例也作为可学习参数）。

### 2. 三步嵌套预测 Pipeline

直接在大规模训练上拟合混合定律代价极高。论文嵌套使用三类 Scaling Laws：

1. **训练步数 Scaling Law**：用小步数实验预测大步数损失
2. **模型大小 Scaling Law**：用小模型预测大模型损失
3. **Data Mixing Law**：在预测的大模型大步数损失上拟合混合定律，从而预测任意新配比的损失

全流程只需小模型（70M–410M）、少量 token（30B）的实验，即可预测 1B 模型在 100B tokens 上、任意数据配比的验证损失。

### 3. 域间关系的系数矩阵

通过可视化 Pile（一个常用的大规模预训练文本集合，包含网页、书籍、代码、学术论文等约 800GB 多领域数据，见 [Gao et al., 2020](https://arxiv.org/abs/2101.00027)）五个粗粒度域的 $t_{ij}$ 矩阵（图4），发现三类关系：
- **Unrelated**（无关）：大多数域对之间稀疏，各自独立
- **Facilitation**（促进）：如 Dialogue 训练数据有助于 Internet 域
- **Conflict**（冲突）：如 Symbolic 数据会损害 Prose 域

### 实践建议：读完这篇论文，能做什么？

论文证明了一个数学事实，但它对实践的意义需要翻译一下：

1. **如果你在从头预训练一个模型**，不要直接拍脑袋决定 web:code:math = X:Y:Z。操作步骤如下：
   - 准备好你的 M 个训练域数据（比如 web、code、math、books）
   - 随机生成约 40 组不同的比例组合（比如 {web:30%, code:50%, math:20%} 这样的向量），每组都跑一遍 70M 模型训练 30B tokens
   - 记录每组配比对应的验证集 loss。"每个域分别记"的意思是：验证集也要按来源拆开，分别算 web 验证集上的 loss、code 验证集上的 loss……而不是把所有域的验证数据混在一起算一个总 loss。这样后面拟合的时候，每个域都有自己的一条曲线，混合定律才能分别对每个域建模。
   - 用这 40 组 (配比 → 各域 loss) 数据拟合混合定律的参数（代码库提供了拟合脚本）。拟合用的正是上面那个指数公式——对每个验证域 i，拟合出 $c_i$、$k_i$、$t_{ij}$ 三组参数，使公式能从配比预测该域的 loss。不需要手动写这个公式，代码库里已经封装好，你只需要提供"(配比, loss 向量)"的数据表格，跑一条命令就能得到参数。
   - 用拟合好的函数枚举或搜索使总损失最小的配比，就是目标配比
   - 在目标规模（比如 1B / 100B tokens）上用这个配比训练
   论文的代码：https://github.com/yegcjs/mixinglaws 包含完整的拟合和搜索实现。

2. **如果你在做持续预训练（continual pretraining）**，这是和第一步完全不同的场景，不是"换个配比"而是"从一个已有模型出发再训练"。动机不同：第一步你没有起点，目标是找全局最优配比；持续预训练你**有一个已经训练好的基座模型**，目标是在不破坏它现有能力的前提下，注入某个新领域（比如代码、医学）的知识。这时候不是找"哪个配比使损失最小"，而是找"新领域数据加多少会开始破坏原来的能力"——两者是截然不同的优化问题。混合定律可以用于预测"临界比例"——加多少新领域数据会开始损害原来的能力，从而精确控制加入量，避免灾难性遗忘。操作步骤如下：
   - 用 4–8 组不同的"原始数据:新领域数据"比例（比如 {Pile:90%+Python:10%}、{Pile:75%+Python:25%} 等）各跑一遍小模型
   - 拟合混合定律，得到"Pile 上的损失随 Python 比例变化"的曲线
   - 找到曲线上与持续预训练前损失持平的临界点，那就是最大安全比例
   - 在该比例以内注入新领域数据，原始能力不会退化

3. **如果你只是想理解现有模型的训练数据结构**，不需要理解公式，只需要看论文图 4（域交互矩阵）。每个格子是绿色意味着"训练这个列的域，有助于提升这个行的域的表现"；灰色意味着无关；红色意味着有冲突。这张图不需要公式就能读懂，直接告诉你哪些领域数据互相促进、哪些互相干扰——比做一堆消融实验再靠肉眼对比直觉得多。

   $t_{ij}$ 矩阵**不完全等于相关系数矩阵**，但直觉上类似。相关系数是线性的、对称的（A 与 B 的相关 = B 与 A 的相关）；$t_{ij}$ 来自指数函数拟合，是非对称的（训练代码数据帮助数学域，不代表训练数学数据同样帮助代码域）。要画这张图，你需要：先完成第一步的 40 组小模型实验并拟合参数，拟合完成后代码库会输出每个验证域的参数文件，其中就包含 $t_{ij}$ 矩阵；把该矩阵归一化（论文用每行的最大绝对值归一化），再用 heatmap 可视化即可。简单说：**拿到拟合参数后，画图是顺手一步**，不需要额外实验。

4. **局限**：这套方法假设排名稳定性（小模型的最优配比 ≈ 大模型的最优配比），这个假设不总成立。实际使用时，最好在中间规模上也做一轮验证。

## 关键结果 / 数据

| 指标 | 结果 |
|------|------|
| 优化后配比 vs 默认 RedPajama | 仅需 **0.73×** 训练步数达到相同 Pile 验证困惑度 |
| 等效提升 | 优化配比等效于默认配比训练 **1.48×** tokens |
| 对比 DoGE、DoReMi | 优化配比在 Pile 验证集上困惑度最低（1B/100B tokens，图9） |
| 预测误差 | 显式域聚合 MAE ≈ 0.003–0.005；隐式聚合误差与显式持平（K≥实际域数） |

**Continual Pretraining 应用**：将混合定律应用于持续预训练（Pythia-70M，Pile + Python code），可精确预测**临界混合比例**（critical proportion）——即在不损害原始域性能的前提下，能加入目标域的最大比例，从而避免灾难性遗忘。

**优化后的 RedPajama 配比**（相比默认大幅调整）：
- CommonCrawl: 67% → 12.5%
- C4: 15% → 25%
- ArXiv: 4.5% → 75%（大幅提升）
- GitHub: 4.5% → 14%

## 局限性

- 拟合混合定律仍需运行多次（约40次）小规模实验，有一定成本
- 嵌套 Scaling Laws 假设小模型/小步数的排名与大模型/大步数一致；若存在**排名翻转**（rank reversal）——即"在小模型上配比 A 比 B 好，但到了大模型上 B 反而比 A 好"——则预测会偏差。这类情况在真实中确实存在，尤其当两个配比在小规模差距很小时。论文引用了 Goyal et al., 2024 等研究该问题的工作，建议在中间规模做一次验证。
- 隐式域聚合的域数 K 需设为不小于实际域数，否则误差会上升
- 实验数据集限于 Pile / RedPajama，对细粒度混合（数十个域）的 scaling 待验证

## 现状与影响

**还在用吗？** 是的，这是数据配比优化领域的代表性定量方法，ICLR 2025 接收，实践价值明确。

**被什么取代？** 尚无直接替代；同期工作包括 DoGE（Fan et al., 2024）和 RegMix（Liu et al., arXiv:2407.01492），思路相似但方法不同。Data Mixing Laws 的优势在于显式函数形式和可解释的域间关系矩阵。

**一句话定性**：将数据配比优化从"经验调参"变成"可预测的定量科学"，是 Scaling Laws 研究从模型维度扩展到数据维度的标志性工作。

## 附录：代码库快速上手

代码库地址：https://github.com/yegcjs/mixinglaws

**核心流程三步：**

**第一步：准备实验数据**

用不同配比各跑一遍小模型训练，把每次训练的结果整理成一个 CSV/JSON，格式大致为：
```
mixture_id, domain_web, domain_code, domain_math, loss_web, loss_code, loss_math
0,          0.5,        0.3,         0.2,          2.85,     1.92,      3.10
1,          0.3,        0.5,         0.2,          2.91,     1.81,      3.08
...
```
每一行是一次实验：前几列是各域训练比例，后几列是各域验证 loss。

**第二步：拟合混合定律**

```bash
python fit_mixing_law.py --data experiments.csv --output params.json
```
脚本会对每个验证域拟合那个指数公式，输出参数文件 `params.json`。

**第三步：搜索最优配比**

```bash
python optimize_mixture.py --params params.json --output best_mixture.json
```
脚本枚举或用梯度搜索找使总损失最小的配比，结果就是你的目标训练配比。

具体参数和脚本名以代码库实际为准，上面是示意流程。若要接入三步嵌套 pipeline（先用 scaling law 外推到目标规模再优化），参考 Algorithm 1 和 `README`。
