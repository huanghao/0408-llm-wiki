# 矩阵书写惯例：行向量 vs 列向量

深度学习论文和代码里，同一个矩阵运算经常有两种截然不同的写法，让人困惑。这篇文档澄清这两种惯例的区别，帮助在读论文和写代码时快速转换。

---

## 两种惯例

### 代码惯例（行向量，PyTorch/NumPy 标准）

数据以**行向量**存储，每个样本/token 是一行：

```python
x: [L, D]   # L 个 token，每个 D 维，每行一个 token
Q = x @ W_Q   # W_Q: [D, D_out]，结果 [L, D_out]
```

矩阵乘法规则：`[m, k] @ [k, n] → [m, n]`，**内维度相消**。

### 数学/论文惯例（列向量）

数据以**列向量**存储，每个样本/token 是一列：

$$Q = W_Q x, \quad x: [D, L], \quad W_Q: [D_{out}, D], \quad Q: [D_{out}, L]$$

读起来更像数学里的线性变换 $f(x) = Wx$，但 $W$ 和 $x$ 的顺序与代码相反。

---

## 两种写法的对应关系

同一件事，两种写法：

| 代码写法 | 数学写法 | 说明 |
|---------|---------|------|
| `Q = x @ W_Q` | $Q^T = W_Q x$ | 转置关系 |
| `Q = F.linear(x, W)` | $Q = x W^T$ | PyTorch `linear` 内部做了转置 |
| `[L, D] @ [D, D_out]` | $[D_{out}, D] \cdot [D, L]$ | 同一个运算，行/列方向相反 |

**快速判断方法**：看到论文里的 $W x$ 写法，只需要记住"内维度相消"的原则，把 $x$ 的维度反过来想（从 `[D, L]` 变成 `[L, D]`），就能对应到代码里的 `x @ W.T`。

---

## 为什么两种惯例都存在

- **数学传统**：线性代数里列向量是标准，$y = Wx$ 更接近"函数作用在向量上"的直觉
- **计算机实现**：行向量在内存里更高效（row-major 内存布局，相邻行元素在内存里连续）；批量数据自然表示为 `[batch, feature]`

现代深度学习框架（PyTorch/TensorFlow/JAX）都采用行向量惯例。读论文时只需要知道"可能是列向量写法，对应代码需要转置"，不需要深究。

---

## 实际读论文的建议

遇到 $Q = W_Q x$ 这类写法时：

1. 不要被维度顺序困住，先理解"这在做什么变换"
2. 对应到代码：`Q = x @ W_Q.T`（行向量版本）
3. 验证：内维度相消，输出 shape 合理即可

大多数 Transformer 论文（Attention is All You Need、BERT、GPT 等）都用列向量写法，但代码实现全部是行向量。
