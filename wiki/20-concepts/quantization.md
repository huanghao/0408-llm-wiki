# 量化

一句话总结：量化是在尽量少损失能力的前提下，用更低精度表示模型权重与激活，从而把开放权重模型从“实验室可跑”变成“个人设备可跑”。

## 是什么

大模型原始权重通常以 FP16 或 BF16 存储。量化会把这些高精度数值压缩成更低位宽的表示，比如 8-bit、6-bit、4-bit，甚至更低。

目标通常有三个：

1. 降低显存或内存占用
2. 降低带宽压力，提高推理吞吐
3. 让更大的模型进入单机或端侧部署范围

## 为什么它对开放权重特别重要

闭源 API 模型的主要瓶颈是调用价格；开放权重模型的主要瓶颈往往是部署成本。

如果没有量化：

- 7B–8B 模型在很多个人设备上都偏重
- 30B–32B 模型很难进入单卡
- 70B 级别几乎只能多卡或服务器

而有了成熟量化后：

- 7B / 8B 成为个人设备的默认本地模型
- 14B / 32B 进入高配笔记本和消费级 GPU 的可用区间
- 70B 级别开始具备更广泛的私有化部署价值

所以量化不是附属优化，而是开放权重生态能否普及的核心基础设施。

## 常见精度层级

| 精度 | 大致特点 | 常见用途 |
|------|---------|---------|
| FP16 / BF16 | 原始或接近原始精度，占用最高 | 训练、对精度敏感的推理、基线评测 |
| INT8 / 8-bit | 损失较小，部署相对稳 | 服务端推理、保守量化 |
| 6-bit | 折中方案 | 一些追求质量和内存平衡的本地部署 |
| 4-bit | 开放权重本地部署最常见甜蜜点 | 个人电脑、单卡、常见本地助手 |
| 更低位宽 | 压缩极强，但质量和稳定性更敏感 | 极端端侧、实验性部署 |

## 代价是什么

量化不是白拿的，代价通常体现在：

1. 精度下降
   数学、代码、长链推理、结构化输出这类任务通常更敏感。

2. 不同模型对量化耐受度不同
   同样是 4-bit，一个模型几乎无感，另一个模型可能明显变笨。

3. 不同实现差异很大
   同样写“4-bit”，底层算法、校准方式、是否做 group-wise / per-channel、是否量化激活，效果都可能不同。

4. 工具链约束
   你能否顺畅部署，往往取决于 `llama.cpp`、`MLX`、`vLLM`、`TensorRT-LLM`、`AWQ`、`GPTQ`、`GGUF` 等工具链是否支持该模型结构。

## 实务判断

如果只是要快速判断：

- 首先看模型是否有成熟社区量化版本
- 其次看目标任务是否高度依赖推理稳定性
- 再看你的硬件是统一内存、消费级 GPU，还是多卡服务器

经验上：

- 4-bit 是大多数个人设备的默认起点
- 需要更稳的代码/推理时，可以往更高精度退
- MoE 模型不能只按“总参数”估算成本，还要看 active 参数和实现支持
