# 强化学习基础

## 监督学习解决不了什么问题

你已经熟悉监督学习（SFT）：给模型一批 `(输入, 正确输出)` 对，让模型的预测尽量接近正确答案。梯度从"答错了多少"直接反传回模型参数。

这套方案有一个隐藏前提：**你得知道什么是正确答案**。

很多场景里这个前提不成立：

- 下围棋：落子对不对，只有整局结束才知道
- 写一首诗：没有唯一正确答案，只有"好不好"的感觉
- 训练 AI assistant：你可以告诉模型"这个回答更好"，但说不出"正确的回答是什么字"

共同点：**奖励信号在序列结束后才出现，且不告诉你"哪一步对哪一步错"**。

强化学习（RL）就是为这类问题设计的框架——不依赖"正确答案"，只依赖"结果好不好"的信号来学习。

---

## 核心框架：agent 和环境

RL 用五个概念描述所有这类问题：

| 概念 | 通用含义 | 围棋里的对应 | LLM 训练里的对应 |
|------|---------|------------|----------------|
| **环境（Environment）** | 提供状态、执行动作、给出奖励的系统 | 棋盘规则 | 奖励模型 + 问题集 |
| **Agent** | 做决策的学习者 | 棋手 AI | 语言模型 |
| **状态（State）** | 当前局面的完整描述 | 棋盘上的落子情况 | 已生成的 token 序列 |
| **动作（Action）** | agent 可以做的选择 | 在哪个位置落子 | 下一个 token 选哪个 |
| **奖励（Reward）** | 环境对动作的评分 | 赢棋 +1，输棋 -1 | 奖励模型打分 / 答案对错 |

整个训练循环就是：agent 观察状态 → 选一个动作 → 环境给出新状态和奖励 → agent 用奖励更新自己 → 重复。

---

## 策略（Policy）是什么

**策略 = 在当前状态下，选择每个动作的概率分布。**

用 $\pi(a|s)$ 表示：在状态 $s$ 下，选择动作 $a$ 的概率。

直觉：策略不是一个规则表（"如果 A 就 B"），而是一个概率分布——面对同一个局面，可以有多种选择，各有概率。训练初期策略是随机的（所有动作概率相等），训练后策略学会了"在什么局面下倾向什么动作"。

**代码示例：老虎机（`src/rl_bandit.py`）**

最简单的 RL 场景：只有一个状态，5 个动作（5 台机器），奖励是随机的。

```
python src/rl_bandit.py
```

代码会输出 500 次模拟的收益/风险统计表和成本敏感性分析。五种策略的典型结果：

| 策略 | 均值 | 标准差 | 最差10% | 夏普 | 风险等级 |
|------|------|--------|---------|------|---------|
| 随机策略 | 160 | 10 | 148 | 0.0 | 低 |
| 纯贪心 | 225 | **93** | **51** | 0.7 | **高⚠** |
| ε=0.1 | 251 | 35 | 199 | 2.6 | 中 |
| ε=0.3 | 247 | 16 | 228 | **5.5** | 低 |
| ε-decay | **275** | 25 | **255** | 4.5 | 低 |

- 纯贪心的**标准差 93**，是 ε-decay 的 3.7 倍——均值看起来不错，但最坏情况只有 51（锁在了赢率 10% 的机器上）
- ε-decay 的**均值最高（275）且下行保护最好（最差 255）**，最接近理论上限 300
- **夏普比率**（超额收益/风险）：ε=0.3 最高（5.5），但均值低于 ε-decay；如果追求稳定优先，选 ε=0.3；如果追求总收益，选 ε-decay

## 探索与利用（Exploration vs Exploitation）

每次决策都面临这个选择：

- **利用（Exploitation）**：选当前看起来最好的动作（收益确定但可能不是最优）
- **探索（Exploration）**：尝试不熟悉的动作（可能发现更好的，也可能浪费机会）

纯贪心策略的问题不是"每次都输"，而是**结果完全取决于运气**——初始化时锁对了就接近最优，锁错了就一路输到底（标准差 93 的来源）。ε-decay 通过主动探索找到最优机器，然后逐渐收敛，把这个随机性基本消除（标准差 25）。

这个权衡在所有 RL 场景里都存在。MCTS 的 UCB 公式是这个权衡的另一种解决方案（见 [MCTS wiki](./mcts.md)）。

**固定成本不改变策略排名**：如果每局都有固定成本 $c$（比如手续费），总成本是 $500c$，对所有策略一样。它平移所有策略的净收益，但不改变均值的相对差距，也不改变标准差。唯一的影响是：**成本越高，越需要高效策略**——当 $c=0.4$ 时随机策略净亏损，只有贪心以上的策略才能盈利。代码里可以把 `COST_PER_ROUND` 改成不同值观察。

## V 值、Q 值、Advantage：三种"好不好"

这五个概念要按顺序理解，每一个都建在前一个上。用一个投资类比串起来。

---

### 第一步：Reward vs Return——单步收益 vs 总收益

**Reward $R_t$**：第 $t$ 步的**即时收益**，环境直接给出。

投资类比：今天这笔交易赚了 5 元。

---

**Return $G_t$**：从第 $t$ 步出发，**到游戏结束为止的总收益**，但未来的收益要打折：

$$G_t = R_t + \gamma R_{t+1} + \gamma^2 R_{t+2} + \cdots$$

折扣因子 $\gamma$（通常 0.9～0.99）的作用：100 步后才能拿到的 1 元，现在只值 $\gamma^{100}$ 元（约 0.37 元）。

投资类比：从今天开始，未来所有收益折现后的**净现值（NPV）**。这就是为什么要用 Return 而不是 Reward——单步奖励根本没法评估一个决策的好坏，只有把后续所有影响都算进来才有意义。

Return $G_t$ 是**一次实际走法的结果**，有随机性——同一个局面走两遍，因为后续随机事件不同，Return 可能差很多。

---

### 第二步：V 值——Return 的期望（"平均来说这个格子值多少"）

$G_t$ 有随机性，每次都不一样。**V 值**就是把随机性去掉：

$$V(s) = \mathbb{E}[G_t \mid \text{从状态 } s \text{ 出发，按当前策略走}]$$

它是"如果从状态 $s$ 出发，反复走很多次，平均能拿到多少 Return"。

投资类比：某只股票的**期望净现值**——不是某一次的实际收益，而是长期平均。

**G 和 V 的本质区别**：
- $G_t$：这一次从 $s$ 出发实际拿了 42 分（单次采样，有随机性）
- $V(s)$：从 $s$ 出发平均能拿 38 分（多次平均，消除随机性）

V 值不知道是怎么到这个状态的，也不知道接下来要走哪步——它只是说"**身处这个状态，按现有策略，未来期望值是多少**"。

---

### 第三步：Q 值——"如果我在这个状态**先走这一步**，然后按策略走，期望多少"

V 值对应"在这个状态，策略会怎么选就怎么走"。Q 值在此基础上多一个约束——**第一步强制走动作 $a$**：

$$Q(s, a) = \mathbb{E}[G_t \mid \text{状态 } s, \text{先走动作 } a, \text{之后按策略走}]$$

投资类比：
- $V(s)$：这家公司的期望净现值（你的策略会自动选最好的投资方向）
- $Q(s, \text{买入})$：如果**这一刻强制买入**，然后按策略操作，期望净现值
- $Q(s, \text{卖出})$：如果**这一刻强制卖出**，然后按策略操作，期望净现值

**V 和 Q 的本质区别**：

V 是"你的策略在这个状态会做的选择的平均结果"——策略已经隐含在里面了。

Q 是"如果第一步**指定走某个具体动作**，之后再按策略走，结果是什么"——它把第一步单独拿出来评估。

关系：$V(s) = \sum_a \pi(a|s) \cdot Q(s,a)$，即 V 是各个动作的 Q 值按策略概率加权平均。

格子世界里看输出：
```
V(起点) = 1.81  ← 按最优策略，从这里出发期望得 1.81 分
  ↑   Q = 0.63   Advantage = -1.18
  ↓   Q = 1.81   Advantage = +0.00  ← 最优动作
  ←   Q = 0.63   Advantage = -1.18
  →   Q = 1.81   Advantage = +0.00
```

V=1.81 是"按策略走的平均"。向下走 Q=1.81（等于 V），说明策略本来就选这个方向，没有额外损失。向上走 Q=0.63，比平均差了 1.18 分。

---

### 第四步：Advantage——"这个动作比平均好多少"

$$A(s, a) = Q(s, a) - V(s)$$

$V(s)$ 是基准（按策略走的平均期望）。$A > 0$ 表示这个动作比策略的平均选择更好，$A < 0$ 表示更差。

投资类比：某个具体操作（买入/卖出）比"按你的正常策略操作"多赚或少赚多少。

Advantage 的用处：训练时用它更新策略，因为它消除了"这个状态本身就好/差"的干扰——只保留"**这个动作相对于正常做法的额外贡献**"。比如一个好局面（V 很高），随便走一步都不差；我们不想因为这个就表扬"随便走一步"。Advantage 为 0 说明这个动作就是策略的正常选择，不需要特别表扬或惩罚。

---

关系总结：
```
R(t)    → 第 t 步的即时奖励（单步，稀疏，有随机性）
G(t)    → 从第 t 步到终局的折现总收益（一次实际轨迹，有随机性）
V(s)    → 从状态 s 出发的期望 G（多次平均，消除随机性，策略已内含）
Q(s,a)  → 从状态 s 强制走动作 a 后的期望 G（第一步固定，之后按策略）
A(s,a)  → Q(s,a) - V(s)，这个动作比策略均值好多少
```

> **关于 Return 和多年收益总和的类比**：完全正确。$G_t = R_t + \gamma R_{t+1} + \gamma^2 R_{t+2} + \cdots$ 就是金融里的**折现现金流（DCF）**，$\gamma$ 相当于 $\frac{1}{1+r}$（折现因子），$r$ 是贴现率。V 值就是期望 NPV，Q 值就是"强制做某个决策后"的期望 NPV，Advantage 就是某决策相对于"按正常策略"的超额价值。这不只是类比——它们背后是同一套数学框架。

## 策略梯度：REINFORCE

前面的格子世界用的是"表格法"——把每个状态的 V 值存在一张表里。状态空间小时可行，但围棋有 $10^{170}$ 种局面，语言模型的状态是所有可能的 token 序列，都无法建表。

解决方案：**用神经网络参数化策略和价值函数**，然后用梯度下降优化。

REINFORCE 是最基础的策略梯度算法：
$$\nabla_\theta J(\theta) = \mathbb{E}\left[ G_t \cdot \nabla_\theta \log \pi_\theta(a_t|s_t) \right]$$

直觉：如果这条轨迹 Return 高（$G_t > 0$），就提高沿途每个动作的概率；Return 低就降低。乘以 $\nabla \log \pi$ 而不是直接对采样求导，是为了绕开不可微的采样操作（原理见 [REINFORCE wiki](./reinforce.md)）。

**方差问题**：直接用 $G_t$ 噪声很大——同一个好动作，有时因为后来运气差而得到低 Return，梯度信号很嘈杂。

常用修复：减去基线（通常是 V 值估计）：
$$\nabla_\theta J = \mathbb{E}\left[ (G_t - V(s_t)) \cdot \nabla_\theta \log \pi_\theta(a_t|s_t) \right] = \mathbb{E}\left[ A(s_t,a_t) \cdot \nabla_\theta \log \pi_\theta \right]$$

这就是为什么 RL 算法最终都在用 Advantage——它是对"这个动作真正的贡献"最干净的估计。

## Actor-Critic：两个网络同时训练

REINFORCE 的问题：必须等完整一局结束才能更新，且 $G_t$ 估计方差大。

Actor-Critic 的解法：同时维护两个网络：

- **Actor（策略网络）**：给定状态，输出动作概率分布 $\pi(a|s)$
- **Critic（价值网络）**：给定状态，估计 V 值

每走一步就更新，不用等到结局。用 **TD error（时序差分误差）** 作为 Advantage 的近似：

$$\delta_t = R_t + \gamma V(s_{t+1}) - V(s_t)$$

含义：$R_t + \gamma V(s_{t+1})$ 是"实际得到的奖励加上下一状态的预期"，$V(s_t)$ 是 Critic 的预测。两者之差就是"这步比预期好了多少"——正的就提高 Actor 这个动作的概率，同时把 Critic 的预测往上调；负的反之。

**代码示例：Actor-Critic 训练格子世界（`src/rl_actor_critic.py`）**

```
python src/rl_actor_critic.py
```

可以看到：
- 前 200 局：平均回报约 -1（随机乱走，经常掉陷阱）
- 400 局后：平均回报 +4 到 +5（学会了绕开陷阱走向终点）
- 最终策略和格子世界里用策略迭代找到的最优策略一致

两个网络互相依赖：Critic 准确了，Actor 才能得到好的梯度信号；Actor 好了，Critic 见到的轨迹质量更高，估计也更准。

## 到 PPO 只差一步

Actor-Critic 有一个实践问题：每步更新幅度没有控制，可能一次更新把策略改得太多，之后的轨迹质量急剧下降（"策略崩溃"）。

PPO（Proximal Policy Optimization）在 Actor-Critic 基础上加了一个约束：

$$\text{clip}\left(\frac{\pi_\theta(a|s)}{\pi_{\theta_\text{old}}(a|s)}, 1-\epsilon, 1+\epsilon\right)$$

本质是限制新旧策略的概率比不能偏离太远——每次更新只走一小步，保证训练稳定。

细节见 [PPO 逐行讲解](./ppo-explained.md)。

## 知识地图：RL 概念的演化线

```
老虎机（无状态）
  ↓ 加入状态转移
格子世界（表格法 V/Q）
  ↓ 状态空间太大，改用神经网络
REINFORCE（策略梯度）
  ↓ 减少方差，不等完整一局
Actor-Critic（TD 误差）
  ↓ 约束更新幅度
PPO / GRPO（见 RLHF wiki）
  ↓ 应用到语言模型后训练
InstructGPT / DeepSeek-R1
```
