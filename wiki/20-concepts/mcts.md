# Monte Carlo Tree Search（MCTS）

## 是什么

Monte Carlo Tree Search（蒙特卡洛树搜索，MCTS）是一种通过随机采样来估计决策价值、并逐步构建搜索树的算法。它不需要精确的价值函数，也不需要穷举搜索，而是通过"模拟游戏到结束"来估计当前局面的好坏。

最初因在围棋 AI 中大获成功（AlphaGo 的核心组件之一）而广为人知，近年在 LLM 推理中被重新引起关注，作为 test-time compute 的一种重要形式。

---

## 核心思想：用随机模拟代替精确评估

在很多决策问题里，判断"当前状态有多好"是困难的，但"模拟走到结局，看最终赢没赢"是容易的。MCTS 利用这一不对称：

- **不需要**：精确的局面评分函数（value function）
- **需要**：从任意状态出发随机模拟到结局的能力（rollout policy）

通过大量随机模拟，用结果的平均胜率来近似当前状态的价值。模拟越多，估计越准。

---

## 四个步骤（每次迭代）

MCTS 反复执行以下四步，逐步扩展搜索树：

```
         ① Selection
        根节点
       /    \
      A      B          ← 用 UCB 公式选择最有潜力的路径
     / \    / \
    C   D  E   F

         ② Expansion
    到达叶节点后，扩展一个新子节点 G

         ③ Simulation（Rollout）
    从 G 出发，用随机策略模拟到终局

         ④ Backpropagation
    将模拟结果（胜/负）沿路径传回，更新每个节点的统计值
```

### ① Selection（选择）

从根节点出发，沿树向下选择子节点，直到到达**叶节点**（未完全扩展的节点）。

选择依据 **UCB1（Upper Confidence Bound）公式**，平衡"利用已知好的路径"和"探索未知路径"：

$$\text{UCB1}(v) = \frac{W(v)}{N(v)} + c \sqrt{\frac{\ln N(\text{parent})}{N(v)}}$$

- $W(v)$：节点 $v$ 累计赢的次数
- $N(v)$：节点 $v$ **被访问的次数**——每次 Selection 经过这个节点、或在这个节点做 rollout，就算"访问一次"，$N$ 加 1
- $N(\text{parent})$：**父节点**的访问次数，即"当前层总共做了多少次模拟"。在只有一层（根节点 → 叶节点）的场景里，$N(\text{parent})$ 就是所有选项的访问次数之和
- $c$：**探索系数**，控制"探索未知"和"利用已知"的权重比例。$c$ 越大，越倾向于多探索访问次数少的节点；$c=0$ 则退化为纯贪心（只选胜率最高的）。$\sqrt{2}$ 是理论上对二值奖励（0/1）最优的值，实践中常调整为 1.0–2.0。
- 第一项：**利用**——$W(v)/N(v)$ 就是该节点的**胜率**（赢的次数 ÷ 总模拟次数），胜率高的节点优先
- 第二项：**探索**——设计成 $\sqrt{\ln N(\text{parent}) / N(v)}$ 有三层意图：
  - $\ln N(\text{parent})$：随总迭代数缓慢增长（对数速度），保证即使已经做了很多次探索，算法仍然会偶尔回来看访问少的节点，而不是彻底放弃它
  - $1/N(v)$：访问次数越多，这项越小——自然地"惩罚"已经被充分探索的节点
  - 整体加 $\sqrt{}$：把量纲压缩，避免第二项在早期（$N$ 很小时）数值过大完全压制第一项。平方根让"探索奖励"随访问次数增加以 $1/\sqrt{N(v)}$ 的速率衰减，数学上可以证明这使得累计遗憾（regret）的增长速度只有 $O(\sqrt{T \ln T})$（见 #11）
  - **渐近行为**：当 $N(v) \to \infty$ 时，第二项趋向 0，UCB 值趋向节点真实胜率——算法最终只靠胜率做决策，完全"收敛到利用"

### ② Expansion（扩展）

到达叶节点后，如果该节点不是终局状态，扩展其中一个（或全部）未尝试过的子节点，加入搜索树。

### ③ Simulation / Rollout（模拟）

从新扩展的节点出发，**用某种策略快速模拟（roll out）**直到游戏结束，得到一个结果（胜/负/得分）。

> **Rollout** 这个词来自"把骰子滚出去"——意思是从当前局面出发，让游戏自己滚到结局，看结果。在围棋里就是从当前盘面一直随机下棋到终局；在 LLM 推理里就是从当前推理前缀一直生成到完整答案，然后用 verifier 检查答案对不对。"Rollout"和"Simulation"在 MCTS 语境里是同义词。

**Rollout 策略的选择对收敛速度影响很大**：
- **随机策略（uniform random）**：最简单，每步等概率选择任意合法动作。收敛慢，但对复杂游戏几乎没有先验偏差，不会引入错误的归纳偏置
- **启发式策略（domain heuristic）**：用人工规则（如"优先走边角"）或轻量分类器快速估分。收敛快很多，但依赖先验知识质量——坏启发可能让搜索方向跑偏
- **神经网络策略（policy network）**：AlphaGo 的做法，用训练好的 policy net 给出每步的概率分布，收敛速度大幅提升，但每次 rollout 需要一次 forward pass，计算更重

**量化对比**（来自围棋研究，Chaslot et al. 2008）：相同计算预算下，随机策略需要约 3,000 次模拟才能在 9×9 围棋上超越人类初学者；引入简单启发（禁止自杀、倒数等）只需约 300 次；policy network 只需约 50 次。LLM 推理场景没有类似的系统性对比，但经验上 verifier 引导的 rollout 比纯随机生成要高效 5–10 倍。

这一步是"Monte Carlo"的来源：用随机（或近随机）采样来近似期望值，不精确但计算快。

### ④ Backpropagation（反向传播）

将模拟结果沿路径传回根节点，更新路径上**每一个经过的节点**的 $W$（累计得分）和 $N$（访问次数）。

具体更新规则：假设 rollout 结果为 $r$（赢=1，输=0），路径上每个节点 $v$ 都执行：
$$W(v) \leftarrow W(v) + r, \quad N(v) \leftarrow N(v) + 1$$

**为什么要更新路径上所有节点而不只更新叶节点？** 因为 Selection 阶段用 UCB 选路径时，路径上的每个节点都"消费"了一次探索机会——如果只更新叶节点，中间节点的 $N$ 不增加，UCB 第二项就不会减小，算法会重复选同一条路径。更新所有中间节点，才能让 UCB 正确反映"这条路径已经被探索了多少次"。

### 具体跟踪：前 3 次迭代在 1×3 格子游戏上

用一个极简游戏说明四步怎么运转：棋盘只有三格（位置 L / M / R），你只能选一格落子，落子后随机决定胜负（L 赢率 30%，M 赢率 60%，R 赢率 40%，你不知道这个概率）。

**初始状态**：树只有根节点，三个子节点 L / M / R 均未访问（$N=0$）。

**迭代 1**：所有子节点 $N=0$，UCB 为无穷大，随机选 L。Rollout：输（$r=0$）。  
→ **反向传播**：L 的 $W \leftarrow 0+0=0$，$N \leftarrow 0+1=1$；根节点 $N \leftarrow 0+1=1$  
→ 状态：L: $W=0, N=1$；M: $W=0, N=0$；R: $W=0, N=0$

**迭代 2**：M 和 R 未访问（$N=0$，UCB 无穷），随机选 M。Rollout：赢（$r=1$）。  
→ **反向传播**：M 的 $W \leftarrow 0+1=1$，$N \leftarrow 0+1=1$；根节点 $N \leftarrow 1+1=2$  
→ 状态：L: $W=0, N=1$；M: $W=1, N=1$；R: $W=0, N=0$

**迭代 3**：R 未访问，先选 R。Rollout：赢（$r=1$）。  
→ **反向传播**：R 的 $W \leftarrow 1$，$N \leftarrow 1$；根节点 $N \leftarrow 3$  
→ 状态：L: $W=0, N=1$；M: $W=1, N=1$；R: $W=1, N=1$

**迭代 4**（三个节点都访问过了，开始用 UCB，父节点 $N(\text{parent})=3$）：

$$\text{UCB}(L) = \frac{0}{1} + \sqrt{2} \cdot \sqrt{\frac{\ln 3}{1}} = 0 + 1.48 = 1.48$$
$$\text{UCB}(M) = \frac{1}{1} + \sqrt{2} \cdot \sqrt{\frac{\ln 3}{1}} = 1 + 1.48 = 2.48$$
$$\text{UCB}(R) = \frac{1}{1} + 1.48 = 2.48$$

M 和 R 并列最高，随机选 M。Rollout：赢。  
→ M: $W=2, N=2$

随着迭代增加，M 的胜率会稳定在 60%（大数定律：$W/N \to 0.6$），UCB 第一项越来越大；而 L 的胜率只有 30%，第一项拖后腿。最终算法会把大部分模拟预算分给 M，少量给 R，极少给 L——**不需要提前知道真实概率，靠采样自动学出来**。

**关于探索效率**（#11 补充）：UCB1 算法有严格的理论保证，Auer et al.（2002）证明其累计遗憾（regret，即"如果一直选最优臂，比 UCB 能多赢多少次"）满足：
$$\text{Regret}(T) \leq O\left(\sqrt{KT \ln T}\right)$$
其中 $K$ 是选项数，$T$ 是总迭代数。这意味着随着模拟次数增加，平均每次的"损失"以 $O(\sqrt{\ln T / T})$ 的速度趋向 0——算法最终一定收敛到最优选项，且收敛速度有理论上界，不会因为探索而无限浪费预算。

## 一个直觉例子：五子棋

假设当前局面，你在考虑三个落子位置 A、B、C：

- 对 A 模拟 100 次：赢 60 次 → 胜率 60%
- 对 B 模拟 20 次：赢 14 次 → 胜率 70%，但样本少，不确定
- 对 C 模拟 80 次：赢 30 次 → 胜率 37.5%

**UCB 会让你继续探索 B**（虽然 B 胜率看起来最高，但访问次数少，置信区间宽，第二项会很大）。随着对 B 的模拟增加，如果 B 真的好，胜率会稳定在高位；如果是偶然高，胜率会回落。最终选择访问次数足够多、且胜率最高的路径。

### 可运行的最小实现：三臂老虎机上的 MCTS

> **三臂老虎机（3-armed bandit）** 是概率论中的经典问题：面前有 3 台老虎机（slot machine），每台有未知的赢钱概率，每次只能拉一台，目标是在有限次数内赚尽量多的钱。它是 MCTS 单层场景的完美模型——"拉哪台机器"等价于"选哪个子节点"，"赢钱概率"等价于"节点的真实胜率"。名字里的"bandit"来自"one-armed bandit"（独臂强盗），是老虎机的俗称。

用上面 L/M/R 的例子，完整代码在 `scripts/mcts_bandit.py`，直接运行：`python3 scripts/mcts_bandit.py`

运行后会看到：M 被访问最多，估计胜率逐渐逼近 0.6；L 被访问极少，早期探索后就被放弃。典型输出：

```
迭代  10 次后：
  L: 访问   3 次，估计胜率 0.33（真实 0.3）
  M: 访问   4 次，估计胜率 0.50（真实 0.6）
  R: 访问   3 次，估计胜率 0.33（真实 0.4）

迭代 200 次后：
  L: 访问  11 次，估计胜率 0.27（真实 0.3）
  M: 访问 154 次，估计胜率 0.59（真实 0.6）
  R: 访问  35 次，估计胜率 0.43（真实 0.4）

最终选择：M（真实最优：M）
```

M 得到了 77% 的预算，L 只有 5.5%——算法自动把计算资源集中在最有价值的选项上。

## 关键特性

| 特性 | 说明 |
|---|---|
| **不需要完整搜索** | 靠采样而非穷举，适合分支因子极大的问题（围棋 $\sim 250^{150}$）|
| **不需要精确价值函数** | 只需能模拟到终局即可 |
| **时间越多越好** | 计算预算越多（迭代次数越多），估计越准，是天然的 test-time compute 策略 |
| **渐进式改进** | 随时可以停下来，用当前最优节点做决策 |
| **探索与利用自动平衡** | UCB 公式保证不会过早收敛到局部最优 |

## 在 LLM 推理中的应用

### 为什么 MCTS 和 LLM 推理相关

LLM 的推理生成可以自然地建模为树搜索：
- **节点**：当前已生成的 token 序列（推理链的前缀）
- **动作**：下一步生成什么 token / 什么推理步骤
- **终局评估**：最终答案是否正确（由 verifier 或答案检查判断）

问题和博弈问题相似：答案质量难以在中间状态精确评分，但"模拟到最终答案然后验证"是可行的。

### 具体用法

**替代简单 best-of-N 采样**：best-of-N 是并行生成 N 个独立解，选最好的。MCTS 则是**有结构的探索**——在早期分叉处多花计算资源，避免 N 个解都走了同一条错误路线。

**Reasoning 树搜索（Tree of Thoughts / MCTS + LLM）**：

```
根：问题
  ├── 解题思路 A
  │     ├── 步骤 A1（展开，模拟后续，发现死路）
  │     └── 步骤 A2（展开，模拟后续，得分高）✓
  └── 解题思路 B
        └── 步骤 B1（尚未探索）
```

LLM 充当两个角色：
- **生成器**：给出候选的下一步推理（扩展子节点）
- **模拟器**：快速产生完整答案用于评估（rollout）

Verifier / reward model 给出最终得分，反向传播更新搜索树。

### AlphaGo / AlphaZero 的做法

AlphaGo 用神经网络替换了 MCTS 的两个关键部件：
- **策略网络（policy network）** 替换纯随机的 rollout policy（即随机模拟策略）→ Selection 时直接给出高质量候选动作，不再随机乱走
- **价值网络（value network）** 替换"从当前局面跑完整 rollout 到终局"→ Simulation 时直接对当前局面打分，不需要一直走到结束

这大幅提升了效率。对应到 LLM 场景：用一个 LLM 当 policy（生成候选推理步骤），用另一个 LLM 或 reward model 当 value（在中间步骤就能估分），就构成了类似 AlphaZero 的推理搜索系统。

### MCTS 和 PPO 的关系

两者经常出现在同一个 LLM 训练管线里，但扮演的角色不同：

| | MCTS | PPO |
|---|---|---|
| **阶段** | 推理时（inference/test time）| 训练时（training time）|
| **作用** | 在搜索空间中找到高质量答案（exploration）| 用找到的高质量答案更新模型参数（optimization）|
| **输入** | 当前模型 + 问题 | MCTS 搜索到的 (state, action, reward) 轨迹 |
| **输出** | 最优推理路径 | 更新后的模型（下次 MCTS 表现更好）|

AlphaZero 的训练循环就是这两者的结合：① 用当前模型跑 MCTS 自我对弈，产生高质量棋局数据；② 用这批数据训练 policy/value 网络（类似 PPO）；③ 新模型更强，再跑 MCTS……如此迭代。

在 LLM 推理训练里（如 o1/DeepSeek-R1 的路线），也有类似思路：用 MCTS 找到正确推理链 → 用 PPO/GRPO 在这些正确链上强化模型 → 模型推理更准 → 继续迭代。两者的关键区别是：MCTS 解决"如何高效搜索"，PPO 解决"如何用搜索结果更新模型"。

## MCTS vs 其他搜索策略

| 策略 | 计算方式 | 适用场景 |
|---|---|---|
| Greedy 贪心 | 每步选当前最优 | 快，但容易陷入局部最优 |
| Beam Search | 保持 k 条最优路径 | NLP 解码常用，但 k 条路径可能相关性高 |
| Best-of-N | 独立采样 N 次选最好 | 简单，但 N 个样本相互独立，不共享信息 |
| **MCTS** | 自适应树搜索，UCB 平衡探索利用 | 时间越多越好，搜索空间大，verifier 可用 |

MCTS 比 Beam Search 更灵活（不固定宽度），比 Best-of-N 更高效（共享早期探索结果）。

---

## 局限性

- **需要 verifier 或终局信号**：MCTS 依赖对最终结果的评分。若 verifier 不可靠，搜索可能收敛到错误方向
- **推理成本高**：每次 rollout 都需要完整地跑一遍到终局，对 LLM 来说意味着多次 forward pass
- **树可能很深**：数学推理等任务的推理链可能有几十步，树深度大时存储和管理开销显著
- **不适合流式生成**：需要先构建树再决策，与当前 LLM 的顺序生成范式有冲突

| **复杂问答 / Tree of Thoughts** | LLM 生成候选思路作为子节点，MCTS 决定哪条思路值得继续展开 | 适合需要多步规划、容易走偏的任务 |
| **强化学习训练数据生成** | MCTS 自我对弈产生高质量轨迹，用于训练 policy/value 网络（AlphaZero 迭代循环）| 与 PPO/GRPO 结合；MCTS 找轨迹，RL 更新模型 |
| **规划 / 机器人决策** | 状态空间巨大但可模拟时，用 MCTS 代替穷举规划；无人驾驶场景规划是典型案例 | 需要快速的状态转移模拟器 |
| **组合优化（搜索辅助）** | 把 NP-hard 问题的搜索空间建模为树，MCTS 用于局部搜索而非全局穷举 | 实验性，不如 SAT solver 等专用工具成熟 |

**选 MCTS 的信号**（同时满足越多越适合）：
1. 搜索空间极大，无法穷举
2. 有可靠的终局评估信号（verifier / reward）
3. 计算预算可变——时间越多，结果越好
4. 早期分叉的质量差异明显（值得结构化探索，而非独立采样）

**不适合 MCTS 的场景**：verifier 不可靠、需要流式实时输出、推理链极长导致树深度不可控。
