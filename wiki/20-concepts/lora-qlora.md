# LoRA 与 QLoRA

一句话总结：LoRA 通过在冻结的预训练权重旁边插入低秩矩阵来微调大模型，把可训练参数从数十亿降到数百万；QLoRA 在此基础上把基础模型量化到 4-bit，让单张消费级 GPU 微调 65B 模型成为可能。

---

## 核心问题：全参数微调的内存瓶颈

理解 LoRA 的出发点是先弄清楚 full fine-tuning 有多贵。

以 7B 参数模型为例，用 BF16 精度训练时，显存需求大致如下：

| 项目 | 每参数字节数 | 7B 模型占用 |
|------|-------------|------------|
| 模型权重（BF16） | 2 bytes | ~14 GB |
| 梯度（BF16） | 2 bytes | ~14 GB |
| Adam 优化器状态（FP32 × 2） | 8 bytes | ~56 GB |
| **合计** | **~12 bytes** | **~84 GB** |

结论：7B 模型 full fine-tune 大约需要 **80–90 GB 显存**，远超单张 A100 80GB 的上限，更不用说消费级 GPU。

这个"4× 参数量字节"的经验法则来自 Adam 的特性：它为每个参数维护两个 FP32 的动量项（一阶矩 m 和二阶矩 v），合起来是 8 bytes/参数，加上权重和梯度各 2 bytes，共 12 bytes——约等于参数量字节数的 4 倍（若权重用 FP16 计算的话是 16 bytes，但通常混合精度下主权重用 FP32 存一份，计法略有差异，量级相同）。

---

## LoRA 原理

### 低秩分解

LoRA（Low-Rank Adaptation，Hu et al. 2021）的核心思想是：**不直接修改预训练权重 W，而是在旁边加一个低秩的增量 ΔW**。

对于一个形状为 d × k 的权重矩阵 W，LoRA 引入两个小矩阵：

```
ΔW = B × A
其中 B ∈ R^{d×r}，A ∈ R^{r×k}，r ≪ min(d, k)
```

前向传播时，输出变为：

```
h = W·x + ΔW·x = W·x + B·A·x
```

训练时 **W 被冻结**，只训练 B 和 A。

### 为什么低秩假设合理

大模型的权重矩阵维度很高（比如 4096 × 4096），但研究发现这些矩阵的**内在维度（intrinsic dimensionality）很低**——权重变化实际上分布在一个低维子空间里。

直觉上：预训练已经把知识编码进了高维权重，fine-tuning 只是在这个基础上做任务适配，所需的"方向性变化"并不需要占满整个参数空间。实验也支持这一点：rank r = 8 或 16 的 LoRA 在很多任务上接近 full fine-tuning 的效果。

### 初始化与缩放

- **A** 用高斯分布随机初始化
- **B** 初始化为全零，保证训练开始时 ΔW = 0，不破坏预训练起点
- 前向传播时对 ΔW 乘以缩放系数 **alpha/r**，完整更新为：

```
h = W·x + (alpha/r) · B·A·x
```

---

## 关键超参数

**r（秩）**：低秩矩阵的秩，控制 LoRA 的参数量和表达能力。

- 通常取 8–64
- r 越大，可训练参数越多，表达能力越强，但内存和计算开销也越大
- 任务差异小（如格式调整、风格迁移）：r = 8 或 16 通常够用
- 任务差异大（如跨领域知识注入）：可以尝试 r = 32 或 64

**alpha（缩放系数）**：控制 LoRA 更新的幅度，实际生效的缩放是 alpha/r。

- 常见设置是 alpha = r（即 alpha/r = 1）或 alpha = 2r
- 增大 alpha 相当于给 LoRA 更新更大的学习率
- 实践中 alpha 和 r 的比值比绝对值更重要

**target modules（应用层）**：决定在哪些权重矩阵上加 LoRA。

- 最常见的做法：只加在 Transformer 注意力层的 **Q（query）和 V（value）投影矩阵**上
- 更激进的做法：Q/K/V/O 全部加，甚至延伸到 FFN 层
- 经验上：Q + V 是性价比最高的起点；如果任务复杂或效果不够，再扩展到更多层

---

## 训练时内存省在哪

LoRA 的内存节省来自两个方面：

**1. 可训练参数大幅减少**

以 7B 模型、r = 16、只加 Q/V 为例，LoRA 参数量约为原始参数量的 0.1%–1%。梯度和 Adam 状态只需要为这些参数分配，不需要为冻结的 W 分配。

**2. 冻结权重不需要存梯度**

W 冻结意味着反向传播不需要对 W 计算梯度，也不需要存储 W 对应的 Adam 状态。这是最大的节省来源。

实际效果：同样是 7B 模型，LoRA 微调通常只需要 **16–20 GB 显存**（用 BF16 基础模型），而不是 full fine-tune 的 80+ GB。

---

## 推理时合并：零额外延迟

训练结束后，LoRA 权重可以直接合并回基础模型：

```
W' = W + (alpha/r) · B·A
```

合并后的 W' 和原始 W 形状完全相同，推理时不需要任何额外计算，**延迟为零**。

也可以选择不合并，把 LoRA 权重单独存储，在推理时动态加载——这样可以用同一个基础模型切换不同的 LoRA adapter，适合多任务部署场景。

## QLoRA：在量化基础上跑 LoRA

QLoRA（Dettmers et al. 2023）把 LoRA 的思路推进了一步：**在 4-bit 量化的基础模型上运行 LoRA 训练**。

### 三个关键技术

**1. NF4（Normal Float 4-bit）量化**

普通 INT4 量化假设权重均匀分布，但神经网络权重通常接近正态分布。NF4 是专为正态分布设计的 4-bit 数据类型，在相同位宽下精度损失更小。

**2. Double Quantization（双重量化）**

量化本身需要存储量化常数（quantization constants）。QLoRA 对这些量化常数再做一次量化，进一步压缩内存占用，平均每个参数额外节省约 0.37 bits。

**3. Paged Optimizer（分页优化器）**

利用 NVIDIA 统一内存（unified memory）机制，在 GPU 内存不足时自动把优化器状态换页到 CPU 内存，避免 OOM 崩溃。

### QLoRA 的效果

- 基础模型以 4-bit NF4 加载，显存占用约为 BF16 的 1/4
- LoRA adapter 仍以 BF16 精度训练
- 实测：65B 模型可以在**单张 48 GB GPU**上完成微调
- QLoRA 微调的 Guanaco 65B 在 Vicuna benchmark 上接近 ChatGPT 水平

---

## 实践中的关键决策

**r 选多大？**

| 场景 | 推荐 r |
|------|--------|
| 格式/风格调整、少样本任务适配 | 8–16 |
| 领域知识注入、中等复杂任务 | 16–32 |
| 复杂任务、跨领域迁移 | 32–64 |
| 接近 full fine-tune 效果 | 64–128（收益递减） |

**哪些层加 LoRA？**

- **只加 Q/V**：参数最少，通常是最先尝试的配置
- **加 Q/K/V/O**：注意力机制全覆盖，效果更稳
- **加 FFN**：FFN 层参数量大，加进来收益明显但代价也高
- **全部层**：接近 full fine-tune 的表达能力，但失去了 LoRA 的大部分效率优势

经验法则：先用 Q/V + r=16 跑基线，效果不够再逐步扩展。

## 局限性

LoRA 不是万能的，有几类场景需要注意：

**任务差异太大**：如果目标任务和预训练分布差异极大（比如让一个英文通用模型学习专业医学知识），低秩的 ΔW 容量可能不够，需要更大的 r 或 full fine-tune。

**多任务干扰**：单个 LoRA adapter 同时学多个差异很大的任务时，任务间可能互相干扰。解决方法是为不同任务训练独立的 adapter，推理时按需切换。

**量化叠加的精度损失**：QLoRA 在 4-bit 量化基础上训练，基础模型本身已有精度损失。对于需要极高精度的任务，这可能是一个瓶颈。

**Adapter 合并的局限**：合并多个 LoRA adapter（比如同时应用两个不同任务的 adapter）在数学上并不总是等价于分别训练的效果，是一个活跃的研究方向。

## 现状与影响

LoRA 由 Hu et al. 在 2021 年提出（arXiv 2106.09685），最初针对 GPT-3 的 fine-tuning 场景。

**成为行业标准**：HuggingFace 在 PEFT（Parameter-Efficient Fine-Tuning）库中实现了 LoRA，配合 Transformers 生态，LoRA 成为开源社区微调大模型的默认方法。目前几乎所有主流开源 LLM（LLaMA、Mistral、Qwen、DeepSeek 等）的社区微调都以 LoRA 为基础。

**QLoRA 的民主化效应**：QLoRA（Dettmers et al. 2023，arXiv 2305.14314）发布后，在消费级 GPU（如 RTX 3090/4090 24GB）上微调 7B–13B 模型成为常规操作，大幅降低了个人和小团队参与模型定制的门槛。

**贡献与实现路线的分离**：LoRA 原论文的核心贡献是低秩假设和训练方案；工程实现（PEFT 库、bitsandbytes 量化后端、unsloth 等加速框架）是独立演化的。实际使用中，"用 LoRA 微调"几乎总是通过这些工具库而非手动实现。

**后续发展**：LoRA 衍生出多个变体，包括 AdaLoRA（自适应调整不同层的秩）、DoRA（把权重分解为幅度和方向分别训练）等，但基础 LoRA 仍是最广泛使用的版本。
