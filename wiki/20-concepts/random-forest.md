# 随机森林（Random Forest）

## 是什么

随机森林是一种集成学习（ensemble learning）方法：**训练很多棵决策树，让它们投票决定最终结果**。

- **决策树**：根据特征逐步分叉，像一棵树一样把数据划分成不同类别
- **随机**：每棵树只看数据的一个随机子集，以及特征的一个随机子集——这让每棵树都"不一样"
- **森林**：多棵树的结果取多数投票（分类）或平均（回归）

## 为什么要用很多棵树

单棵决策树的问题是**过拟合**——它会把训练数据记得太死，对新数据泛化差。

随机森林的解法是**多样性 + 平均**：
- 每棵树都有些不同（因为训练数据和特征都是随机子集）
- 每棵树可能各自有偏差，但偏差的方向不同
- 取平均后，各自的偏差相互抵消，整体更稳健

类比：问 100 个背景不同的人同一个问题，取多数意见，比只问一个"专家"更可靠。

## 工作原理（三步）

```
1. Bootstrap 采样（有放回抽样）
   从 N 个训练样本里，随机有放回地抽 N 个（有些样本会被重复抽到，有些不会被选到）
   → 每棵树的训练集略有不同

   "Bootstrap"来自统计学术语，指"有放回地重采样以估计分布"。
   举例：原数据 [A, B, C, D, E]，bootstrap 一次可能得到 [A, A, C, D, E]（A重复，B缺失）。
   每棵树从这样一份"扰动版"数据上训练，天然就有了差异。

2. 随机特征子集
   每次分裂节点时，不是考虑所有特征，而是随机选 k 个特征（通常 k = sqrt(总特征数)）
   → 每棵树关注的"视角"不同

3. 投票/平均
   分类：每棵树投一票，取票数最多的类别
   回归：每棵树输出一个数，取平均
```

## 和决策树的对比

| | 单棵决策树 | 随机森林 |
|--|----------|---------|
| 过拟合风险 | 高（容易记住训练数据） | 低（多样性 + 平均抵消偏差）|
| 训练速度 | 快 | 慢（训练 N 棵树）|
| 可解释性 | 高（可以画出来看） | 低（100 棵树难以解释）|
| 准确率 | 一般 | 通常更高 |
| 需要 GPU | 不需要 | 不需要 |

## 什么时候适合用随机森林

**适合**：
- 特征是结构化的数值/类别（表格数据、embedding 向量）
- 不需要解释"为什么这样分类"
- 需要快速训练（比神经网络快得多）
- 样本量中等（几万到几百万条）

**训练速度参考**（sklearn，普通 CPU，n_estimators=100）：
| 样本量 | 特征维度 | 训练时间 |
|--------|---------|---------|
| 1 万条 | 100 维 | < 1 秒 |
| 10 万条 | 1024 维 | 10–60 秒 |
| 100 万条 | 1024 维 | 5–30 分钟 |

phi-1 的 10 万条 × 1024 维 embedding，单机 CPU 上约 30–60 秒训练完。对比：同规模数据训练一个 MLP 需要额外调参，且通常需要 GPU。

**不适合**：
- 原始图像、文本、音频（这类数据需要神经网络来提取特征）
- 需要端到端可微分训练（随机森林不能反向传播）
- 极高维度、极稀疏特征（如 one-hot 编码的百万维词袋）

## 在 phi-1 里的用法

phi-1 用随机森林做代码质量分类器：

```python
# 特征：codegen-350M-mono 模型对每个代码文件的 embedding（1024 维向量）
# 标签：GPT-4 给 10 万个样本打的教育价值分（0-10）

from sklearn.ensemble import RandomForestClassifier

clf = RandomForestClassifier(n_estimators=100)
clf.fit(code_embeddings, gpt4_scores)   # 10 万条（embedding, score）对

# 对全量 35B tokens 的每个文件打分，保留高分
scores = clf.predict(all_embeddings)
high_quality = [f for f, s in zip(all_files, scores) if s >= threshold]
```

**为什么选随机森林而不是神经网络**：
1. **训练快**：10 万条样本的随机森林秒级到分钟级训练完，神经网络需要更多调参
2. **不需要 GPU**：embedding 已经提取好了，随机森林在 CPU 上跑
3. **效果足够**：任务是质量打分（0-10 的回归，或阈值二分类），特征（embedding）已经很有表达力，不需要更复杂的模型

**推理速度参考**（sklearn，单 CPU 核）：
| 样本量 | 特征维度 | 推理时间 |
|--------|---------|---------|
| 1 万条 | 1024 维 | < 1 秒 |
| 100 万条 | 1024 维 | 10–30 秒 |
| 3500 万条（35B tokens / ~1000 token/文件估算） | 1024 维 | 5–15 分钟 |

phi-1 对全量 35B tokens 打分（约 3500 万个代码文件），在单机 CPU 上约 10 分钟内完成，远快于再跑一遍神经网络推理。

**关于任务形式**：GPT-4 给出的是 0–10 的分数，严格说是回归任务（预测一个连续值）或 11 分类，不是二分类。实践中常见的做法是：用随机森林预测分数，再用一个阈值（如 ≥ 7 分）来决定是否保留——最终决策是二分类，但中间的打分是连续的。phi-1 论文里没有明确说是分类还是回归，两种做法都合理。

这个"强模型打标 → 轻量分类器 → 规模化"的模式不是随机森林独有的，DCLM 等后续工作也用了类似思路，只是分类器换成了 fastText。

**fastText 作为分类器是什么意思**：fastText 原本是一个词向量工具，但它也有文本分类功能——给定一段文本，直接预测类别标签（如"高质量"/"低质量"）。DCLM 的做法是：用 GPT-4 标注一批文本的质量，训练一个 fastText 文本分类器，再用它对全量数据打分过滤。和 phi-1 的区别在于特征：phi-1 用神经网络 embedding 作为随机森林的输入特征，DCLM 的 fastText 直接吃原始文本的词袋特征，不需要先跑一次大模型提取 embedding——所以 fastText 更快，但理论上特征表达力不如 embedding。两者都是"轻量代理"的实例，解决的是同一个问题。

## 重要超参数

| 超参 | 含义 | 经验值 |
|------|------|--------|
| `n_estimators` | 树的数量 | 100–500，越多越稳定但越慢 |
| `max_features` | 每次分裂考虑的特征数 | 分类 `sqrt(n)`，回归 `n/3` |
| `max_depth` | 树的最大深度 | `None`（不限，让树长到底）|
| `min_samples_leaf` | 叶节点最少样本数 | 1–5，越大越防过拟合 |
